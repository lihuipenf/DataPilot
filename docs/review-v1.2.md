# DataPilot v1.2 检查报告

检查日期：2026-11-04。范围：模型边界、配置隔离、会话恢复、网页切换、报告、发布扫描及现有分析执行器。包含独立只读代码审查；不把协议模拟测试视为真实模型准确率。

## 本轮实现及修复

| 检查点 | 结果 |
|---|---|
| 多服务商适配 | DeepSeek / OpenAI Responses（含可用Codex模型）/ Claude Messages / OpenAI兼容 Chat Completions |
| 请求参数隔离 | DeepSeek专用thinking参数不发给其他服务商 |
| 工具连续调用 | Responses保留推理内容及phase；Claude合并并行工具结果，终结步骤保留定义并禁止继续调用 |
| 历史模型来源 | 会话、回答及列表记录provider/model；恢复会话不跟随新的默认服务商 |
| 切换与密钥 | 网页应用模型创建新会话并复制数据；密钥留在服务端，不接入CLI订阅凭据 |
| 异常响应 | HTTP200但结构错误也变为脱敏ModelError，避免终端退出及网页未处理500 |
| 单价与报告 | 更换模型不继承旧单价；修正固定DeepSeek标识和过时内存存储说明 |
| 发布边界 | 扫描.env及环境中所有API_KEY，真实临时Git索引回归；业务数据和凭据仍被忽略 |

## 接下来值得改进的地方

以下来自实际代码检查，按本项目成熟度收益排序。尚未实施，不应写进简历的“已完成”功能。

| 优先级 | 改进 | 当前依据 | 验收方向 |
|---|---|---|---|
| 1 | 多模型、未见数据评测 | `evals/cases.json`的LLM题集仍基于五行样例；`answer_ok`依赖关键词，可能放过自相矛盾回答 | 增加中文商品、并列、缺失日期、大表、注入文本等独立数据；数字与SQL结果核对，按模型报告成功率/延迟/Token并人工抽查 |
| 2 | 进度、取消和整轮期限 | `agent.py`只有工具轮数上限，各HTTP步骤最多重试一次；`static/app.js`等待最终结果，无取消 | 使用SSE展示模型/工具阶段，用户取消，整轮deadline，取消后不提交半轮历史 |
| 3 | 显式资源释放 | `web.py`淘汰/替换会话尚未显式关闭SDK HTTP客户端和`tools.py`懒加载SQLite连接，主要依赖回收 | 定义统一close生命周期，覆盖淘汰、数据替换、关机，验证并发分析时不提前关闭 |
| 4 | 更灵活的数据接入 | `data.py`强制固定四列销售CSV，`semantic/metrics.json`只有当前业务指标 | 先做列映射和字段说明，再做多表及数据库只读连接，提供同口径可重放查询 |
| 5 | 金额精度和币种契约 | `data.py`与SQLite REAL使用浮点数，界面及汇总按两位展示；不包含币种、税费和退货语义 | 明确单价精度/舍入时机，迁移Decimal或最小货币单位，添加边界对账样例 |
| 6 | 共享部署所需的身份及数据隔离 | 当前明确定位单用户本地工具，只有Host检查与随机会话ID，没有用户/租户权限 | 只有扩展到多人服务时再引入鉴权、租户权限、配额和数据保留策略；当前保持本地运行 |

建议下一版优先完成第1和第2项：前者能证明分析可靠性，后者能让较慢模型的使用体验更完整。其后做资源生命周期与数据接入，比继续堆工具数量更有价值。
