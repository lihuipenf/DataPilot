## 已复现并修复

| 等级 | 问题与触发条件 | 修复 |
|---|---|---|
| 高：发布泄露风险 | 源码打包仅检查DeepSeek；其他服务商的凭据若误写进待打包文件仍会进入ZIP | Git与ZIP共用扫描器，覆盖所有本地API_KEY及常见token模式，在创建归档前拦截 |
| 高：发布扫描绕过 | 同名环境变量覆盖.env时，扫描器丢掉文件中的旧密钥，因此旧密钥可混入提交 | 分别收集文件与环境中的值，去重保留两者 |
| 中：计算错误 | `00123` / `123`被推断为同一编号，`1e3`变数字，`NA`被识别成空值 | 商品标识按字符串解析，保留字面名称，仍拒绝真正空字段 |
| 中：工具异常 | 只读SQL参数含大于64位的整数时，SQLite抛OverflowError而非结构化错误 | 捕获转换溢出，返回工具错误；后续查询可继续 |
| 中：条件性跨站修改 | 恶意网页已知目标会话ID时，可发起不需要JSON的简单POST/reset清空历史 | API拒绝不匹配或null Origin，以及跨站/同站不同来源的Fetch Metadata；合法同源请求与无浏览器头的CLI兼容 |
| 中：请求资源消耗 | 只有CSV有限制，普通JSON会先整包读取再检查问题长度 | 在ASGI读取层限制普通API请求16KiB、CSV 5MiB；检查实际流量，读取期限30秒 |
| 中：异常输入500 | 非有限JSON数字、过深结构或孤立代理字符可导致验证响应/UTF-8输出异常 | 支持JSON媒体类型变体，在路由前验证可编码性、有限数字与最大嵌套32层，返回400 |
| 中：模型参数异常 | 模型返回含NaN的工具参数时，虽然工具报错，执行记录仍携带非有限值，导致网页响应失败 | 用户请求与模型参数共用JSON校验，异常参数转为工具错误，执行记录使用安全标记 |

“跨站修改”需要已知随机会话ID；本次未证明攻击网站能跨域读取会话列表。没有把这一条件风险描述为任意远程读取数据。

另增加CSP、禁止嵌入、nosniff、无引用来源及API no-store响应头。手机上传改为外部JS绑定事件。自动 `/docs`、`/redoc` 依赖CDN与内联脚本，已明确关闭；保留机器可读的 `/openapi.json`。源码包排除嵌套运行目录/.env变体，拒绝链接越出项目目录。

## 安全边界与未覆盖项

项目仍是单用户本地应用。Origin/Host检查是浏览器防护，不是身份认证；同一电脑上的恶意进程可以自行构造请求头。不要把随机会话ID当作多人权限机制。默认入口与Compose继续绑定回环地址。

会话数据库以本地明文保存业务数据和对话，依赖文件系统权限；没有引入加密、多租户权限或外网服务认证。模型权限、实际付费接口与第三方Markdown阅读器不在本轮验证范围。

模型服务可选自定义端点，实时请求会发送问题、必要历史及工具证据，SQL结果也可能包含原始行。凭据端点由服务端配置，浏览器不能修改；只能使用你信任的端点。

尚值得继续完善：显式关闭被淘汰会话的模型/SQLite连接、整轮分析deadline与取消、产物空间配额，以及更广的数据/模型评测。这些没有冒充本轮已完成的修复。

复查依据：[PyPA pip-audit](https://github.com/pypa/pip-audit)、[Starlette中间件文档](https://www.starlette.io/middleware/)、[SQLite运行限制](https://www.sqlite.org/limits.html)。
